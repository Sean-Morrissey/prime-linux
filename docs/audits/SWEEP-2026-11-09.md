**The honest answer to "is it broken?"**: the desktop is healthy and the two errors
you saw this week were both real, both fixed, and both had the same shape — a
Hyprland upgrade moved something underneath a component that could not be rebuilt
without help (hyprbars plugin headers). What is missing is not repair, it is
**coverage**: the rebuild only happens at login, so an update taken *while* you are
logged in can leave you without titlebar buttons until you log out and back in.

## 2. What is already automated (so the sweep does not duplicate it)

- Package updates: `prime-system-update.timer`, with snapshot-before-transaction via snap-pac.
- Plugin rebuild after a Hyprland bump: `prime-hyprpm-doctor.service` at login, with a
  guard that *disables* hyprbars rather than half-loading it when a rebuild fails.
- Desktop health: `prime-doctor` (manual, `Super+H`) and `prime-doctor --daily` for
  problems that appear while the session is up.
- Rollback: snapper + snap-pac (boot menu cannot list snapshots on systemd-boot; undo
  is `btrfs-assistant` or `snapper rollback`).

## 3. Workstreams

### A. Infrastructure (the "it keeps breaking" part)
1. **[core]** Move the plugin rebuild *into the update path*, not just login: after
   `prime-system-update.service` finishes and if `hyprctl version` changed, run
   `prime-hyprpm-doctor.sh` immediately. Effect: titlebar buttons survive a live update.
2. **[core]** Add a doctor check that fails loudly when a plugin is **enabled in the
   manifest but not loaded** — today that is only visible if you notice missing buttons.
3. **[core]** Pin the three packages whose bumps actually cost you the desktop
   (`hyprland`, `hyprpm`, `hyprcursor`) to "upgrade only when I say", with a
   one-click "upgrade the desktop stack" action. Everything else stays automatic.
4. **[safe]** `hyprcursor` is in the pending list right now — take it through the
   normal timer, then verify cursor theme still resolves.

### B. Appearance
5. One theme source: confirm bar, dock, GTK, Qt, cursors and titlebar buttons all
   read from `~/.config/prime/theme/` (doctor already checks most of this).
6. Titlebar buttons: audit hover/press states and the zoom button's behaviour on
   tiled vs floating windows.
7. Wallpaper: the shifted "starts below the bar" image I made is a one-off — fold the
   34 px offset into `prime-theme` so *any* wallpaper lines up with the bar.
8. Cursor + icon consistency after the hyprcursor bump (Papirus-Dark + one cursor theme).

### C. Accessibility
9. Text scale: a single control that moves GTK, Qt, terminal, browser and bar at once
   (today: separate knobs).
10. Contrast/high-contrast variant of the theme from the same colour file.
11. Keyboard-only reachability: audit the 118 binds for a complete path to every
    surface the bar exposes (they should all be reachable without a mouse).
12. Motion: a reduce-animations toggle at the Hyprland level.

### D. Settings
13. `prime-system-settings` audit: every setting reachable from the menu, no dead rows
    (the menu had two dead rows yesterday — same class of bug).
14. Make `prime-doctor` report at login *only* what it could not fix (it already
    supports this), so errors are loud once instead of silent forever.

## 4. Phases and stop criteria

- **Phase 1 — coverage (A1, A2, D14).** Pass: simulate a Hyprland bump (touch the
  version file), run the update path, `hyprctl plugin list` shows hyprbars; doctor
  reports a missing plugin in its output. Stop if the plugin cannot be rebuilt.
- **Phase 2 — pending updates + cursor (A4, B8).** Pass: 0 pending, session still
  healthy after the timer runs.
- **Phase 3 — appearance (B5–B7).** Pass: screenshot before/after; wallpaper aligns
  with the bar for two different images; buttons behave tiled and floating.
- **Phase 4 — accessibility + settings (C, D13).** Pass: text scale moves all five
  surfaces; every menu row resolves; keyboard path to every bar surface.
- **Phase 5 — documentation.** Update the `prime-whiteboard` / bar skills with what
  changed, so the next session does not rediscover it.

## 5. Risks and rollback

- Risk: touching the update path can leave a half-updated system → every phase goes
  through the normal snapper snapshot; #124 is the current pre-update point.
- Risk: pinning Hyprland means missing security fixes → the pin is a *hold*, with a
  visible "desktop stack update available" prompt, not a permanent freeze.
- Rollback: `snapper list` → restore #124 (or the phase's own pre-snapshot) from
  `btrfs-assistant`; plugin-only rollback is `hyprpm disable hyprbars`.
