# What Prime Linux assumes about the software underneath it.
#
# Prime's own tests run when Prime changes. The breaks people actually hit come
# from the other direction: CachyOS and Arch roll forward, an interface Prime
# leans on changes, and nothing noticed until the desktop misbehaved. Hyprland
# 0.57 replacing the whole config language is the clearest case; waybar's
# workspace clicks going silent on 0.57 is the same story one layer up.
#
# So each line below is a promise with a date on it: this component, at this
# version, does the thing Prime needs it to do, and somebody checked.
# .github/workflows/upstream-watch.yml reads this file every week, compares it
# with what the repos ship *now*, and says so in the job summary — so the gap
# shows up in CI on a Monday instead of on somebody's desktop mid-task.
#
# A warning here is not a failure. It means: go and look, then either confirm
# the new version and move the line, or write the port.
#
# Columns, tab- or space-separated:
#   package   tested-up-to   checked-on   what Prime leans on
#
# "tested-up-to" is major.minor — patch releases don't get their own promise.
# Moving a line means somebody ran the desktop (or the test that stands in for
# it) on that version, not that it installed cleanly.
